Segurança em

Entenda como uma aplicação confirma identidades, controla permissões e protege senhas. Use testes para verificar essas regras e refatore o código com confiança.

Objetivo da aula

Aplicar autenticação e autorização em uma aplicação web e melhorar a organização do código, verificando o resultado com testes.

  • Distinguir identidade, perfil e permissão.
  • Explicar a verificação de senhas com BCrypt.
  • Interpretar respostas HTTP e conferir o estado dos dados.
  • Refatorar e registrar as mudanças no Git.

Conceitos da aula

Autenticação

Verifica a identidade de quem acessa uma aplicação. Um login com usuário e senha é uma forma de fazer essa verificação.

Quando a identificação falha?

Em uma API que exige credenciais, o código HTTP 401 indica que credenciais válidas estão ausentes.

Autorização

Verifica se a identidade tem permissão para executar uma operação. O servidor aplica a regra de acesso a cada requisição protegida.

Quando a permissão é insuficiente?

Uma API pode responder com HTTP 403 quando a conta foi identificada e seu perfil não permite a operação.

Hash de senha e BCrypt

O BCrypt gera um hash com um salt aleatório. A aplicação usa o hash armazenado para conferir se a senha informada corresponde à original.

Qual é a função do salt?

O salt faz com que uma mesma senha possa gerar hashes diferentes. Ele é armazenado como parte da representação do hash.

Spring Security

Oferece componentes para proteger aplicações Java com Spring. A equipe usa esses componentes para verificar credenciais e aplicar regras de acesso.

Onde definir uma permissão?

A política de acesso pode definir quais perfis têm permissão para requisitar uma operação protegida.

Clean Code e refatoração

Nomes claros e responsabilidades bem definidas ajudam a localizar as regras. A refatoração melhora a estrutura interna e preserva o comportamento observado.

Como verificar uma refatoração?

Rode os mesmos testes antes e depois da mudança e compare os resultados esperados.

Testes de acesso e Git

Teste operações permitidas e recusadas. Confira o código HTTP e o estado dos dados. Depois, use o Git para registrar as mudanças verificadas.

O que o status HTTP mostra?

Ele resume o resultado da requisição. Uma consulta adicional pode confirmar se o registro foi alterado ou preservado.
